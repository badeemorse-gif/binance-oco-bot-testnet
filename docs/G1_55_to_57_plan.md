## G1.55 — تصحيح نسبة رسالة إعادة التموضع في الواجهة (إزالة «اللغبطة»)
- **severity:** major (عرض/دلالة؛ لا أثر تنفيذي على التداول).
- **المشكلة (مُثبتة من القرص):** على حدث `event=="REPOSITIONED"` تبني الواجهة رسالة
  «تم التنقل من التموضع إلى أمر جديد OCO … بناءً على %s …»، و`%s` يأتي من `_bound_touched_for`
  التي — حين يكون السعر **بين** الحدّين — تُعيد «أقرب حدّ» (`abs(p-lower) <= abs(p-upper)`)،
  فتنسب التموضع إلى «الحد العلوي X» رغم أن القوس **لم يُلمَس**. (مثال المستخدم: سعر 104.72،
  علوي 105.5، سفلي 103 ⇒ المسافة للعلوي 0.78 < للسفلي 1.72 ⇒ ظهر «الحد العلوي 105.5».)
- **الحقيقة البنيوية:** لمس القوس الفعلي يمرّ عبر `BracketMonitor.check` ⇒ **خروج** لا إعادة
  تموضع، ولا يُنتج حدث `REPOSITIONED`. إذن مسار `REPOSITIONED` دائمًا تقريبًا بلا عبور حدّ.
- **القرار المعتمد افتراضيًا = (أ):** نُبقي شكل الرسالة المحبوب ونُصلح النسبة فقط. (إن أردت
  الخيار (ب) «لا تغيير إطلاقًا» أبلِغني قبل الختم.)
- **DoD:**
  1. `_bound_touched_for` لا تُعيد حدًّا إلا عند تحقّق شرط العبور نفسه (`p<=lower` أو `p>=upper`)؛
     وإلّا `(None, None)` (تُحذف خوارزمية «أقرب حدّ»).
  2. `_order_placed_message` عند غياب الحدّ تستخدم وصفًا صادقًا لإعادة التموضع (مثل
     «إعادة تموضع (مُشغّل الصعود)») بدل «القوس»؛ وعند وجود عبور فعلي تبقى «الحد [العلوي/السفلي] [القيمة]».
  3. تصحيح التعليق المضلِّل قرب معالج `REPOSITIONED` («ملامسة القوس…») ليعكس أنه حدث إعادة تموضع.
  4. §1.5: ترجمة إنجليزية لأي نصّ جديد + تغطية `retranslate_widget_tree`.
- **scope_boundary:**
  - داخل: `ocobot/ui/monitoring.py` (`_bound_touched_for` + `_order_placed_message` + التعليق)،
    `ocobot/ui/i18n.py` (إضافة سلسلة EN فقط)، `tests/test_g1_55_*.py`.
  - **ممنوع:** hot_path (`on_price_tick`/`MonitoringEngine`/`SafeExecutor`/`reposition`/`create_oco`)،
    `ocobot/domain/bracket.py`، `ocobot/alerts/*` (formatting/bridge/notifier)، آلة حالة `ORDER_PLACED` (G1.34)،
    ورسالة تليجرام «🔁 Repositioned» ورسالة `monitor_start`.
- **acceptance_checks:**
  - REPOSITIONED والسعر بين الحدّين ⇒ الرسالة بلا «بناءً على الحد العلوي/السفلي» مختلَق، وتُظهر وصف إعادة التموضع + السعر الحالي.
  - REPOSITIONED والسعر فعلًا `>=upper` ⇒ يظهر «الحد العلوي [القيمة]» (سلوك صحيح محفوظ).
  - اختبار لقطة: رسالة تليجرام `build_reposition_message` و`monitor_start` بلا أي تغيّر.
  - اختبار انحدار: لا تغيّر في مخرجات `ocobot/alerts/*`.
  - §1.5 لكل نصّ جديد.
  - كامل السويت split-per-file أخضر ≥ baseline (788) + الاختبارات الجديدة.
- **expected_evidence:** `docs/G1_55_report.md` + تشغيل `tools/_run_suite_per_file.py`.

## G1.56 — مُرشِّح نِسب تكيّفي للعملة (TP/SL/Trigger) + ملء تلقائي بوضعين
- **severity:** minor (ميزة/تحسين اختياري، عرض/اقتراح فقط).
- **الهدف:** عند اختيار العملة، يقترح المحرّك أفضل `tp_pct`/`sl_pct`/`trigger_pct` من تقلّب
  العملة وحركتها بحيث **لا نخرج مبكرًا** ونلتقط أكبر حركة تتبّع ربحية.
- **المنهج (الأقوى):**
  - مقدّرات تقلّب: `ATR%` (Wilder) للعرض + **Yang-Zhang** (OHLC) أساسًا، واحتياطًا Garman-Klass/Parkinson؛ `EWMA vol (λ≈0.94)` + مئين التقلّب.
  - **المحرّك الأساسي:** توزيعات **MFE/MAE** (أقصى حركة مُواتية/معاكِسة) + **توزيع عمق الارتدادات**.
  - طبقة نظام: `ADX/DMI` + `Hurst`/Variance-Ratio + Choppiness.
  - **فريمات هرمية:** عالٍ (4h/1d) لسياق الاتجاه وطموح الـTP؛ تشغيل (15m–1h) لحجم SL/Trigger؛ منخفض (1m–5m) لأرضية الضوضاء/`gap_ticks`.
  - **الربط (قابل للمعايرة):**
    - `sl_pct ≈ max(k_sl·ATR%_op, P80(MAE))` (k_sl ~1.5–2.5)
    - `trigger_pct ≈ median(pullback)·f` (f ~0.6–0.8)
    - `tp_pct ≈ P75(MFE)·ADX_factor`
    - كله مقصوص على فلاتر العملة (tickSize/LOT_SIZE/minNotional) + أرضية الفلاش-كراش (G1.33).
- **وضعا الملء التلقائي:**
  - **(1) مرّة واحدة (one-shot):** يملأ قبل البدء ثم يتجمّد طوال الجلسة. صفر مخاطر.
  - **(2) متتبّع (tracking):** يُحدِّث النسب بلا إيقاف المراقبة، بضوابط:
    - حساب خارج خيط الواجهة (async) + قيمة مخزّنة؛ النبضة تقرأ المخزَّن فقط ⇒ لا تأخير.
    - التطبيق **بين النبضات فقط** ولا أثناء `in_flight`؛ يؤثّر في **دورة التموضع التالية** (الأمر القائم لا يتغيّر لحظيًا).
    - تحقّق كل قيمة مقابل السعر + الفلاتر؛ `hysteresis` + تهدئة + سقف تغييرات/جلسة (ضد المطاردة).
    - مفتاح **Off/Observe/Live** (الافتراضي Observe) + تدقيق كل تغيير.
- **التحقّق:** منصّة Backtest/معايرة **Walk-Forward** تعيد استخدام منطق التتبّع الحقيقي (dry-run) على شموع
  السوق **الحيّة العامة** (klines قراءة فقط بلا مفاتيح؛ Testnet رقيق للتقلّب)، وتقيس معدّل الخروج المبكر/التقاط MFE.
- **chunks مقترحة:**
  - `c1` (كود): `ocobot/domain/volatility.py` (ATR/Yang-Zhang/EWMA) خالص + tests.
  - `c2` (كود): `ocobot/domain/excursion.py` (MFE/MAE + عمق الارتداد) خالص + tests.
  - `c3` (كود): `ocobot/domain/regime.py` (ADX/Hurst/Choppiness) خالص + tests.
  - `c4` (كود): `ocobot/domain/recommender.py` (الربط ⇒ اقتراحات + clamp للفلاتر) خالص + tests.
  - `c5` (كود): جلب klines عبر الرَنَر (لا شبكة في الواجهة) + cache.
  - `c6` (كود): لوحة «ترشيح النِّسب» (عرض فقط) + زر ملء مرّة واحدة.
  - `c7` (كود): الوضع المتتبّع (Off/Observe/Live) + الضوابط + تدقيق.
  - `c8` (كود): CLI معايرة/Backtest Walk-Forward.
- **scope_boundary:** وحدات domain جديدة خالصة + لوحة UI عرض-فقط + CLI؛ **ممنوع** لمس hot_path أو منطق
  التنفيذ، ولا شبكة في طبقة الواجهة (حارس `test_ui_no_direct_network`)، ولا Live قبل G1.
- **acceptance_checks:** دوال خالصة مُختبَرة + Backtest يثبت تحسّن «عدم الخروج المبكر» + §1.5 + لا شبكة في الواجهة + كامل السويت أخضر.

## G1.57 — توحيد تنبيهات تليجرام لكل وسائل التدخّل برسالة ثريّة موحّدة
- **severity:** major (ثغرة اكتمال: تدخّل حقيقي قد لا يصل بتفاصيل كاملة/متّسقة).
- **الوضع الحالي (مُثبت من القرص):**
  - `monitor_start` + `repositioned`: تُرسَل تلقائيًا عبر `bridge.py` (`_ALERT_EVENTS` = هذين فقط) — ثريّة.
  - الحارس (Position Guardian) + قوس الخروج: تُرسَل عند التدخّل الفعلي عبر `notifier(result)` (G1.37) + `alert_cb` نصّي.
  - حارس هبوط BTC: موصول عبر `btc_alert_cb` (G1.44) — غالبًا نصّ مقتضب بلا تفاصيل كاملة ⇒ ثغرة.
  - القوالب الثريّة `build_guardian_message`/`build_market_exit_message` موجودة في `formatting.py` لكن غير مفعّلة عبر الجسر ⇒ **عدم اتساق المسارين**.
- **DoD:** رسالة ثريّة موحّدة لكل وسيلة تدخّل بنفس حقول رسالة التموضع (الرمز · السبب · الدخول=reference ·
  الخروج/السعر · ربح/خسارة% · الكمية · معرّف الأمر · الوقت) ورأسٌ مميّز لكل خاصية، مع سدّ ثغرة ثراء BTC وتوحيد المسارين،
  **دون تغيير** رسالتَي `repositioned`/`monitor_start` المحبوبتين.
- **أشكال الرسائل المقترحة (رأس + تفاصيل كاملة):**
  - **🛡️ شبكة أمان المركز:** «تدخّل الحارس: نافذة عارية تجاوزت العتبة» + وقف حمائي عند X.
  - **🧷 قوس الخروج (الحد العلوي):** «لمس الحد العلوي [القيمة]» + سعر الخروج (أفضل bid).
  - **🧷 قوس الخروج (الحد السفلي):** «لمس الحد السفلي [القيمة]» + سعر الخروج.
  - **⬇️ حارس هبوط BTC:** «انحدار BTC مؤكّد — نسبة التتبّع %» + التضييق/الخروج.
  - **✋ خروج يدوي:** «بأمرك — أفضل سعر لحظي». (G1.47)
- **scope_boundary:** `ocobot/alerts/*` (توحيد القوالب + التوجيه) + نقاط الإطلاق في wiring فقط؛
  **ممنوع** لمس hot_path/منطق التنفيذ، ولا تغيير رسائل `repositioned`/`monitor_start`.
- **acceptance_checks:** كل وسيلة تُطلق رسالة ثريّة موحّدة عند التدخّل الفعلي (PLACED) + BTC يحصل على التفاصيل الكاملة +
  اختبار لقطة لعدم تغيّر رسالتَي التموضع/البدء + §1.5 + كامل السويت أخضر.
